About

A local software-house control panel for multi-agent development, built on opencode. One tool, six role agents, different free models per role — coordinated through plain status files instead of a message bus, so the whole protocol is just text you can read in any editor.

<User> ──► AGENTIX (http://127.0.0.1:9999)
│
├── creates/links a project (folder/repo, any stack e.g. Laravel PHP)
├── initializes .agents/ + tasks/board.md + CLAUDE.md + role config
├── spawns opencode run --agent <role> -m <model> "task"
│ (runs inside the project folder, with real tool use)
└── renders live: agent statuses, task board, run logs, handoffs, versions
Installation

Recommended. Everything runs inside the container — portal, opencode CLI, Playwright Chromium, LibreOffice, Node. No host dependencies beyond Docker and Git.

1
Clone the repo:
$ git clone https://github.com/myherokuu/agentix-code.git
$ cd agentix-code
2
Install Docker if you don't have it:
macOS — brew install --cask docker (open Docker Desktop once)
Linux — sudo apt-get install docker.io docker-compose-plugin
Windows — Docker Desktop (needs WSL2)
3
Run bootstrap script (checks Docker, sets up .env, starts everything):
$ ./bootstrap/run-myagents.sh
4
Or manually with Docker Compose:
$ cp .env.example .env # edit PROJECTS_DIR
$ docker compose -f docker/compose.yml up --build

Register projects using paths under /workspace/projects/... (where PROJECTS_DIR is mounted). Runtime state lives in the myagents-data Docker volume.

Docker auto-restart: docker/compose.yml sets restart: unless-stopped — Docker restarts the container on crash, on any OS.

Runs directly on your machine. ./run.sh installs Python deps, Playwright Chromium, and opencode automatically if missing.

How the agentic system works

The contract: Registering a project writes a CLAUDE.md — the rules every spawned agent reads before doing anything. Read your assignment, read docs/ and tasks/board.md first, commit with role prefix, append to .agents/<role>.status on every state change.

RolePurposeFolder
PM Orchestrates: reads every status file, assigns tasks, routes work .
BA Requirements — BRD/FRD, user stories, API specs docs/
DEV Implements features, fixes bugs, writes unit tests src/
QA Writes test cases, runs them, reports bugs, verifies fixes tests/
DBA Schema design, migrations, query optimization db/
INFRA Docker, CI/CD, deployment, security review infra/
PM is the only coordinator. Agents never talk to each other directly. Cross-role handoffs go through .agents/handoffs.json. The one exception is Agent Meeting — an opt-in multi-agent discussion feature.
The run lifecycle
1
Checkpoint before — working tree committed as-is, even if nothing changed. Always a point to revert to.
2
Agent runs — inside project folder via opencode, with real file-edit and shell tools. Risky actions pause for approval.
3
Checkpoint after — another commit captures whatever changed, whether or not the agent made its own explicit commit.
4
Status + board update — agent appends to .agents/<role>.status; portal reconciles tasks/board.md.

Beyond one-shot runs

Chat Agents

Plan-only conversation with any role (or General / Internal Documents) that never touches files or the board.

Adaptive Loop

SIGNAL → SENSE → DECIDE → ACT → FEEDBACK → ADAPT background cycle.
Three modes: observe (detect + explain), suggest (propose, wait for approval), auto (safe decisions only).

Agent Meeting

Deliberate exception to "PM-only coordination" — spin up actual multi-role discussions, transcribed live.

Protocol
Agents talk only through .agents/*.status files: TIMESTAMP | STATE | MESSAGE
States: INIT PENDING ASSIGNED IN_PROGRESS DONE FIXED BLOCKED REVIEW CANCELLED
Commits use role prefixes: [PM] [BA] [DEV] [QA] [DBA] [INFRA]
PM is the only coordinator; no direct agent-to-agent chat

Observability (optional)

Traces agent runs, LLM calls, and DB queries to Langfuse — self-hosted or Cloud. Connect via the Observability tab or .env variables (LANGFUSE_HOST, LANGFUSE_PUBLIC_KEY, LANGFUSE_SECRET_KEY). Leave unset to disable.
