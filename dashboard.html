About

A local software-house control panel for multi-agent development, built on opencode. One tool, six role agents, different free models per role — coordinated through plain status files instead of a message bus, so the whole protocol is just text you can read in any editor.

<User> ──► AGENTIX (http://127.0.0.1:9999)
│
├── creates/links a project (folder/repo, any stack e.g. Laravel PHP)
├── initializes .agents/ + tasks/board.md + CLAUDE.md + role config
├── spawns opencode run --agent <role> -m <model> "task"
│ (runs inside the project folder, with real tool use)
└── renders live: agent statuses, task board, run logs, handoffs, versions
Installation

Recommended. Everything runs inside the container — portal, opencode CLI, Playwright Chromium, LibreOffice, Node. No host dependencies beyond Docker and Git.

1
Clone the repo:
$ git clone https://github.com/myherokuu/agentix-code.git
$ cd agentix-code
2
Install Docker — the one thing this path can't install for you:
macOS — brew install --cask docker (open Docker Desktop once so its daemon is running)
Linux — sudo apt-get install docker.io docker-compose-plugin (Debian/Ubuntu — use your distro's package manager otherwise)
Windows — Docker Desktop (needs WSL2, which its installer sets up). Run the manual docker compose command below from PowerShell — bootstrap/run-myagents.sh is a bash script, so it only runs as-is inside WSL, Git Bash, or macOS/Linux.
3
Run bootstrap script (checks Docker, sets up .env, starts everything):
$ ./bootstrap/run-myagents.sh # from the repo root
4
Or manually with Docker Compose (works on any OS with Docker installed, including Windows PowerShell):
$ cp .env.example .env # edit PROJECTS_DIR to wherever your real project folders live
$ docker compose -f docker/compose.yml up --build

Everything (portal, opencode CLI, Playwright Chromium, LibreOffice, Node) runs inside the container — see docker/Dockerfile and docker/compose.yml. Register projects using paths under /workspace/projects/... (where PROJECTS_DIR gets mounted inside the container), not their original host path. Runtime state (projects.json, runs, chats, PMO...) lives in the myagents-data Docker volume, never in the image.

Auto-restart: already on, no setup needed. docker/compose.yml sets restart: unless-stopped — Docker restarts the container on a crash, on any host OS.

Runs directly on your machine. ./run.sh installs the Python deps and the Playwright Chromium browser itself, and installs opencode automatically if it's missing — it's what every Run Agents / Chat Agents call actually shells out to, so without it, runs fail with a bare "FileNotFoundError" that's hard to root-cause from the UI. If you'd rather not think about any of this, use the Docker path instead — it bundles all four dependencies below.

1
Clone the repo:
$ git clone https://github.com/myherokuu/agentix-code.git
$ cd agentix-code
2
Quick start:
$ cd center
$ ./run.sh # → http://127.0.0.1:9999
3
Optional deps (warned but not auto-installed — the right install command depends on your OS/package manager):
LibreOffice (soffice) — for Documents .docx export and Calc export. brew install --cask libreoffice (macOS) or sudo apt install libreoffice (Linux)
Node.js — for the artifacts-builder skill. brew install node (macOS) or nodesource/nvm (Linux)
4
Optional: auto-restart on crash (macOS only — see note below for other OSes):
$ ./supervisor_install.sh

By default ./restart.sh starts uvicorn as a plain background process — if it crashes, nothing brings it back until you notice. This installs a launchd user agent (~/Library/LaunchAgents/com.myagents.center.plist) with KeepAlive (restarts on crash/non-zero exit, but not after an intentional ./stop.sh) and RunAtLoad (starts on login). ./restart.sh and ./stop.sh detect the installed job automatically and use launchctl instead of manual kill/nohup once it's there. Logs at data/logs/portal.{out,err}.log. Uninstall: launchctl bootout gui/$(id -u)/com.myagents.center && rm ~/Library/LaunchAgents/com.myagents.center.plist. launchd is macOS-only — if you're not on macOS and don't want Docker, auto-restart isn't currently available; ./restart.sh still works, it just needs to be re-run by hand after a crash.

Backups: data/ (projects, chat history, Brain memory, Agent Meetings) is backed up automatically every 6 hours to center/backups/*.tar.gz (last 14 kept, oldest pruned) — runs as a background thread inside the portal itself, already on with no setup. Check the latest backup or trigger one on demand from the Services dropdown next to the online indicator in the topbar.

How the agentic system works

The contract every project gets

Registering a project writes a CLAUDE.md into it — the same rules every spawned agent, whatever its role, reads before doing anything:

Read your assignment (from the PM, or from the prompt you typed directly).
Read docs/ and tasks/board.md first, then work only inside your own domain folder (ba → docs/, dev → src/, qa → tests/, dba → db/, infra → infra/ — configurable per role in agents.json).
Commit with a role prefix: [PM] [BA] [DEV] [QA] [DBA] [INFRA].
Append one line to .agents/<role>.status on every state change: TIMESTAMP | STATE | MESSAGE, states INIT PENDING ASSIGNED IN_PROGRESS DONE FIXED BLOCKED REVIEW CANCELLED. Never overwrite — it's an append-only log, so history is always there to read back.
Never set DONE without a matching commit, and never commit secrets or .env files.
Keep tasks/board.md current — move a task to In Progress when starting it, Done/Blocked when finishing; add a - [ ] T-XXX: row for any new work discovered along the way.
PM is the only coordinator — agents never talk to each other directly. Cross-role handoffs go through .agents/handoffs.json, which the PM writes and the next role reads; there's no agent-to-agent chat channel. (The one deliberate exception is Agent Meeting, a separate, opt-in multi-agent discussion feature for when you want several roles to actually converse.)

This is the whole protocol. No custom message format, no queue to run, nothing to learn beyond "these are plain text files, read them."

Roles

RolePurposeFolder
PM Orchestrates: reads every status file, assigns tasks, routes work, keeps the board honest .
BA Requirements — BRD/FRD, user stories, API specs docs/
DEV Implements features, fixes bugs, writes unit tests src/
QA Writes test cases, runs them, reports bugs, verifies fixes tests/
DBA Schema design, migrations, query optimization db/
INFRA Docker, CI/CD, deployment, security review infra/

Plus two chat-only pseudo-roles that never touch .agents/ or the board: General (broad-knowledge assistant, not tied to any project role) and Internal Documents (answers grounded only in that project's own Documents tab + readable Storage uploads, says plainly when something isn't in there rather than guessing). Every role/model pairing lives in center/agents.json — edit it directly to change names, working folders, descriptions, or which model each role uses.

Coordination model. There is no agent-to-agent message bus by design. The PM is the single point that reads every .agents/*.status file and tasks/board.md, decides what's next, and writes .agents/handoffs.json when a task moves from one role to another. This keeps the whole system debuggable — at any point, "why did DEV do that?" has a plain-text answer sitting in a file, not a conversation buried in an LLM's context window somewhere.
The run lifecycle

Every Run Agents click follows the same sequence, regardless of role:

1
Checkpoint before — the project's working tree is committed as-is ([CHECKPOINT] before {role} run {id}), even if nothing changed, so there's always a point to revert to.
2
The agent runs inside the project folder via opencode, with real file-edit and shell tools. In attended mode (the default), risky actions pause for your approval in the Run Agents tab; unattended background sweeps auto-approve safe patterns only.
3
Checkpoint after — another commit ([AUTO] snapshot after {role} run {id}) captures whatever changed, whether or not the agent also made its own explicit git commit following the [ROLE]-prefix convention.
4
Status + board update — the agent appends to its own .agents/<role>.status; the portal reconciles tasks/board.md against every role's status file afterward, so a task reaches Done even if only one role was expected to move it.

Nothing is ever silently lost: the Versions tab reads this same git history back, split into Local Code (those auto checkpoints), Git Code (commits that actually reached GitHub — pushed or pulled, not just local), Status (pure .agents/*.status/board bookkeeping commits, kept separate from real code), and Documents (Artifacts builds specifically, grouped by the file each one produced) — every version one click from a revert, with a real side-by-side diff.

Beyond one-shot runs

Chat Agents

A plan-only conversation with any role (or General / Internal Documents) that never touches files, .agents/, or the board — for talking through an approach before committing an agent to it.

Adaptive Loop

An opt-in background SIGNAL → SENSE → DECIDE → ACT → FEEDBACK → ADAPT cycle. Every project change (a commit, a failed QA run, a manually reported event) becomes a signal; each tick picks an intent, a role, and a tool (a real run vs. a plan-only consult), acts through the same engine as a manual Run Agents click, and remembers whether it worked.
Three execution modes per project: observe (detect + explain only), suggest (propose, wait for your approval), auto (auto-execute safe decisions only — anything destructive or production-affecting always drops to suggest).

Agent Meeting

The deliberate exception to "PM-only coordination": spin up an actual multi-role discussion when you want several agents to reason about something together, transcribed live.

Agents

Agent Library — every role's current status, at a glance, plus ⚙ Manage Skills: a shared skill catalog (assignable to any role in any project) with full add/edit/delete — editing re-syncs the change into every project that already has that skill assigned, deleting is blocked while a skill's still assigned anywhere.

Project

Tools

Storage — central file manager for anything portal-managed.
Live Browser — a real browser session per project an agent can drive (and you can watch) via HTTP calls.
Sketch — a shared Excalidraw-style canvas an agent can draw on.
Artifacts — one-shot self-contained HTML builds (React/Tailwind bundled to a single file), version-tracked in the project's own git repo.
Documents — a .docx writer with prompt history, stored centrally (not in the project's git repo — see the Versions Documents category above).
Excel / Calc — spreadsheet generation/editing with a query interface.
Visual Builder · Test Workflows (record once via Live Browser, replay deterministically).
API Client — a Bruno-style request builder scoped to each project: collections saved as .bru-style text files in the project's own api/ folder (git-tracked with the code), environments with {{var}} substitution, requests actually sent server-side (so CORS never blocks you), a safe post-response bru.setEnvVar(...) mini-script for chaining tokens between requests, and a ⟳ Sync from code button that discovers endpoints already defined in the project (an OpenAPI/Swagger spec, or Laravel routes/*.php) and imports the ones not in the collection yet.

Project Management

PMO Overview — phases, activities, planned-vs-actual, risks.
Minute Meeting — meeting register, decisions, action tracking.

Observability (optional)

The Observability tab traces agent runs, LLM calls, and DB queries to Langfuse — self-hosted (its own separate stack, see docker/langfuse-compose.yml and langfuse.com/self-hosting) or Langfuse Cloud. Connect it either way, no restart needed:

In the app — open the Observability tab, fill in Host / Public key / Secret key, and save. Stored locally in data/observability_settings.json (secret key never echoed back to the UI after saving).
Via .env — set LANGFUSE_HOST, LANGFUSE_PUBLIC_KEY, and LANGFUSE_SECRET_KEY (used as a fallback whenever the in-app settings are empty; needed for the Docker Compose path).

Leave both unset to keep it disabled with no effect on anything else.
