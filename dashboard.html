◈ About AGENTIX

A local software-house control panel for multi-agent development, built on opencode. One tool, six role agents, different free models per role — coordinated through plain status files instead of a message bus, so the whole protocol is just text you can read in any editor.

<User> ──► AGENTIX (http://127.0.0.1:9999)
│
├── creates/links a project (folder/repo, any stack)
├── initializes .agents/ + tasks/board.md + CLAUDE.md
├── spawns opencode run --agent <role> -m <model> "task"
└── renders live: agent statuses, task board, run logs

⚡ Quick start

$ cd center
$ ./run.sh # → http://127.0.0.1:9999

./run.sh installs Python deps and Playwright Chromium, and installs opencode automatically if missing.

$ ./bootstrap/run-myagents.sh # Docker path

◉ How the agentic system works

The contract: Registering a project writes a CLAUDE.md — the rules every spawned agent reads before doing anything.

RolePurposeOwn folder
PM Orchestrates: reads every status file, assigns tasks .
BA Requirements — BRD/FRD, user stories, API specs docs/
DEV Implements features, fixes bugs, writes unit tests src/
QA Writes test cases, runs them, reports bugs tests/
DBA Schema design, migrations, query optimization db/
INFRA Docker, CI/CD, deployment, security review infra/

▹ The run lifecycle

1
Checkpoint before — working tree committed as-is, even if nothing changed.
2
Agent runs — inside project folder via opencode, with real file-edit and shell tools.
3
Checkpoint after — another commit captures whatever changed.
4
Status + board update — agent appends to .agents/<role>.status; portal reconciles tasks/board.md.
